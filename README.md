# pmnotes.ai Prompts

Open-source collection of Product Management prompts for [pmnotes.ai](https://pmnotes.ai). This repository houses the prompt library used to power the pmnotes application, designed to assist Product Managers in various stages of their workflow.

## Repository Structure

```
prompts/
├── <surface>/              # discovery | prototyping | execution
│   └── <prompt-slug>/      # kebab-case, unique across all surfaces
│       ├── meta.json       # Metadata (title, inputs, tags, etc.)
│       ├── prompt.md       # The prompt template
│       ├── example.md      # Example output
│       └── variations.json # Optional: 2–4 named tweaks to the prompt
├── index.json              # GENERATED: metadata for every prompt (no bodies)
└── search.json             # GENERATED: prompt bodies for full-text search
collections/
├── <collection-slug>.json  # Curated, ordered sequences of prompts (playbooks)
└── index.json              # GENERATED by `npm run index`
scripts/                    # Index builder, validator, allowed values (taxonomy.js)
test/                       # node:test suite
```

The [pmnotes.ai](https://pmnotes.ai) website reads the generated files and the prompt files straight from this repo's `main` branch, so a merge goes live without a website deploy.

### Generated files

`npm run index` writes three files. Commit them with your change; `npm run validate` (and CI) fails if they are stale. Each is a pure function of the files on disk (no git history, no timestamps), so rebuilding unchanged content changes nothing.

- `prompts/index.json`: `{ "items": [...] }`, the `meta.json` of every prompt plus computed fields: `id`, `category` (the surface), `path`, and `contentHash`. It has no prompt bodies, so the site's first load stays small.
- `prompts/search.json`: `{ "items": [{ "id", "prompt" }] }` in the same order, with each `prompt.md` body minus its `# Ground Rules` section (identical boilerplate in every prompt). The site loads it lazily for full-text search.
- `collections/index.json`: `{ "collections": [...] }`, every collection sorted by title.

`contentHash` is the first 12 hex characters of `sha256(meta.json + "\n" + prompt.md)` over the raw bytes. It changes whenever either file changes; the site uses it to warn when a saved draft was made from an older version of the template.

### Deploy hook

Prompt content goes live as soon as it is merged, but the website's prerendered pages and sitemap are built at deploy time. To rebuild the site after every push to `main` (once validation passes), CI calls a Cloudflare Pages deploy hook:

1. In Cloudflare, open the Pages project → **Settings** → **Builds** → **Deploy hooks**, and create a hook for the production branch.
2. In this GitHub repo, go to **Settings** → **Secrets and variables** → **Actions** and add the hook URL as the repository secret `CF_PAGES_DEPLOY_HOOK`.

Without the secret, the `deploy-website` job skips with a notice. Treat the hook URL like a password: anyone who has it can trigger builds.

### Surfaces

Prompts are grouped into three workflows (the folder name is the `surface` value):

- **Discovery** (`discovery`): Strategy, user research, and problem definition (e.g. drafting PRDs, analyzing feedback).
- **Prototyping** (`prototyping`): Building functional prototypes and data models (e.g. generating schemas, frontend components).
- **Execution** (`execution`): Automating technical tasks and analysis (e.g. data analysis, release automation).

## Development

Requires Node.js 24+ (see `.nvmrc`). There are no dependencies to install.

```bash
npm run index      # regenerate prompts/index.json, prompts/search.json and collections/index.json
npm run validate   # validate prompts, collections, and index freshness
npm test           # run the test suite
npm run check      # validate + test
```

## Prompt Structure

Each prompt is a directory containing three essential files:

### 1. `meta.json`

Defines the structure and properties of the prompt.

```json
{
  "slug": "feature-prioritization",
  "title": "Feature Prioritization",
  "shortDescription": "Prioritize features using a framework like RICE or MoSCoW.",
  "surface": "discovery",
  "pmStage": "Strategy & Decision Artifacts",
  "complexity": "Structured",
  "teamScale": "Scaleup",
  "outputType": "Prioritized List",
  "tags": ["prioritization", "roadmap"],
  "jobsToBeDone": ["Rank feature backlog"],
  "inputs": [
    {
      "key": "feature_list",
      "label": "Feature List",
      "example": "Dark mode, Offline support..."
    }
  ]
}
```

Allowed values (enforced by `npm run validate`, defined in `scripts/taxonomy.js`):

- `pmStage`: one of the artifact types in `PM_STAGES` (e.g. `Strategy & Decision Artifacts`, `Requirements & Specifications`, `Data Analysis & Visualizations`)
- `complexity`: `Quick` | `Structured` | `Deep`
- `teamScale` (optional): `Startup / SMB` | `Scaleup` | `Enterprise`
- `inputs[].key`: snake_case, and each key must be used in `prompt.md`
- `inputs[].optional` (optional boolean): the input may be left empty; every use of `{{key}}` must sit inside `{{#if key}}...{{/if}}`. Don't write "(optional)" in the label; the site shows it.
- `id`, `category`, `path`, `prompt` and `contentHash` are computed by the index builder and must not appear in `meta.json`
- `inputs[].options` (optional string array): suggested values shown in the input

### 2. `prompt.md`

The prompt template itself. It uses Handlebars-style syntax `{{variable_name}}` for dynamic inputs defined in `meta.json`. Optional sections can be wrapped in `{{#if variable_name}} ... {{/if}}` (blocks may nest); they are dropped when that input is left empty.

```markdown
# Role

You are a Senior Product Manager...

# Task

Prioritize the following features: {{feature_list}}
...
```

### 3. `example.md`

A static example of what the model should generate, shown on the prompt page. It must be consistent with the example inputs: correct numbers, no invented facts, fictional companies, and code in fenced blocks with a language tag. Examples that start with an HTML tag are previewed in a sandboxed frame.

### 4. `variations.json` (optional)

Named tweaks shown under the prompt, such as a different framework, audience or level of detail. On the site, **Copy with variation** copies the user's filled-in draft followed by a `# Variation` heading and the `promptDelta` text, unchanged.

```json
[
  {
    "name": "RICE scoring",
    "description": "Score each feature on Reach, Impact, Confidence and Effort.",
    "promptDelta": "Use RICE as the framework (this replaces any framework named above).\n- ..."
  }
]
```

- 2–4 entries, each with a non-empty `name` (unique within the file), `description` and `promptDelta`, and no other fields.
- `promptDelta` is appended after the prompt, so write it as an instruction that adjusts or overrides the sections above. It must follow the prompt's Ground Rules: ask for `[DATA NEEDED: ...]` or `(est.)` rather than inviting invented facts.
- The delta is not run through the template engine: `{{#if}}` blocks are rejected, and a `{{key}}` must name an existing input but stays literal text, so prefer plain wording ("our product") over placeholders.
